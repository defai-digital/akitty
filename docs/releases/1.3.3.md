# AkiTTY 1.3.3

- Preserve an integrated native prompt's authorization readiness when human input is empty. Real input still marks the prompt edited, and agent-owned or headless sessions retain their existing rejection behavior.
- Keep SDK sprite playback running when a manual update, clear or replacement write is rejected or throws. Report rejected chrome/title teardown writes as cleanup failures instead of silently reporting successful disposal.
- Validate Web terminal dimensions consistently in the constructor, direct resize and mutable options. Keep wasm, renderer, canvas and options aligned when a resize fails, and invalidate links after committed reflow.
- Retry a failed resize paint when the caller repeats the same dimensions, including through options. Reuse the committed grid and announce the successful resize once, without reflowing or duplicating notifications.
- Reset the Web title/bell scanner and link cache through the common clear path. Release old fit-addon observers and timers on reactivation, and bound proposed dimensions for oversized containers.

Apple Silicon, macOS 14+. SDK source version is 0.2.2. AkiTTY Web remains a separate private source package; embedding applications must adopt and qualify these source changes independently. Agent reports remain unverified and every local command request still requires human approval.
